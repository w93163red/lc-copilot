# LeetCode Copilot

Chrome 侧边栏扩展。打开一道 leetcode.com 题目，点击「生成提示」，扩展把题面发给一个 OpenAI 兼容接口，流式返回若干层递进提示和一份完整代码。提示默认折叠，想看哪层再展开，避免一眼看到答案。

## 安装（加载已解压的扩展程序）

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本仓库目录。
3. 点击工具栏图标即可在当前窗口打开侧边栏。侧边栏绑定打开它时所在的标签页，切到别的标签页不会跟着变；当另一个题目标签页处于前台时，面板顶部会出现「切换到这一题」，点一下就改绑到那一题。

## 配置

右键图标选「选项」，或在侧边栏点「设置」，填写：

- **Base URL**：OpenAI 兼容接口地址，不含 `/chat/completions`，例如 `https://api.openai.com/v1` 或本地 `http://localhost:11434/v1`。
- **API Key**：请求头 `Authorization: Bearer <key>`。
- **模型**：例如 `gpt-4o-mini`。

点「保存」时扩展会申请访问该接口域名的权限（默认只有 leetcode.com）。先保存再点「测试连接」，它会发一次非流式的小请求并显示结果。设置存在 `chrome.storage.local`，不会上传到任何地方。

## 提示的结构

模型只输出若干个「提示 n」二级标题和最后一个「完整代码」标题，扩展按标题切成可折叠区块。提示的层数按题目决定：扩展先单独请求一次模型，让它列出从暴力解走到最优解所需的关键洞察，再按这个数量恰好请求那么多层，加上思考方向和完整步骤两层，所以最少 2 层，没有上限。每一层只新增一个洞察：第一层只给思考方向，不点名算法或数据结构；中间各层各给一个关键观察或该用的数据结构、算法思想；最后一层给完整步骤、边界条件和复杂度，可用伪代码。之后是**完整代码**：按编辑器当前选择的语言给出可直接提交的实现，附「复制」按钮。

流式输出过程中区块逐个出现，已展开的区块在刷新时保持展开。

生成完成的结果按题目存在 `chrome.storage.local`，再打开同一题时直接显示，状态栏标为「已缓存 · 日期」，不再请求模型；缓存的语言和编辑器当前语言不一致时会提示。点「重新生成」会重新请求并覆盖缓存。

## 评估代码

切到「评估」标签点「评估代码」，扩展直接读取页面编辑器里当前的代码（通过 Monaco 的模型，不用复制粘贴），同时读取页面上最近一次 Run 或 Submit 的结果（也会填进「调试」标签的结果框），连同题面一起发给模型，按五个维度返回：**测试追踪**（拿运行结果里的失败用例，没有就拿题面第一个示例，逐步执行代码、写出每步的变量值和最终输出）、**正确性**（必须和追踪一致；只要页面上的结果不是 Accepted，这一节强制以「不正确」开头并指出失败的输入）、**复杂度**（时间和空间、是否已经最优）、**问题**（bug、边界、风格，每条指到具体行）、**改进建议**（具体改法，可能附一小段代码）。五个区块默认展开。有运行结果时状态栏标为「已参考运行结果」，没读到时标为「未读到运行结果，判断仅基于代码追踪」。评估结果只保留在内存里，不写入缓存，编辑器为空时会提示。

## 调试

代码没过的时候切到「调试」标签。扩展会从页面上读取最近一次 Run 或 Submit 的结果（判定、报错，或 Wrong Answer 的输入 / 输出 / 预期）填进「运行结果」框，切到这个标签时框是空的会自动读一次，也可以点「读取结果」重读，或者把报错手动粘贴进去。点「找错」后，扩展把题面、编辑器里的代码和运行结果一起发给模型，返回四个区块：**错误原因**（判定或报错是什么意思、根本原因在哪，会引用失败的输入）、**出错位置**（具体的行或表达式）、**修复思路**（分步骤怎么改，不给完整代码）、**修正后的代码**（完整实现，默认折叠，想看再展开）。运行结果框的内容按题目保存在内存里，切到别的题再切回来还在；诊断结果不写入缓存。

## 开发

无构建步骤，纯 ES module。`npm test` 运行 `node --test`，覆盖分段、SSE 解析、提示词、页面读取、设置校验和提示缓存。

端到端验证 `scripts/e2e.mjs`：起一个本地假 OpenAI 流式服务，用 Playwright 以未打包扩展方式启动有头 Chromium，打开真实的 leetcode.com 两数之和页面，在侧边栏页面里点「生成提示」，断言四个折叠区块、代码块内容和发出的请求；然后在页面里造一个 Wrong Answer 结果，切到「评估」点「评估代码」，断言五个展开的区块、状态栏的「已参考运行结果」和请求里带着编辑器代码与运行结果；再切到「调试」，断言结果框已经被评估读到的结果填好、四个区块的展开状态和请求里带着运行结果与代码；再打开第二道题的标签页，断言面板仍停在原题并出现「切换到这一题」，点击后来回改绑两题，缓存的区块从内存恢复。需要全局安装的 `@playwright/mcp`（或用 `PLAYWRIGHT_MODULE` 指向一个 playwright 包目录）和一个 Chromium 二进制：

```sh
CHROMIUM_PATH="/path/to/Chromium" node scripts/e2e.mjs
```
